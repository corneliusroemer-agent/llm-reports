## 2. EMBL/INSDC flatfile validation — yes, and it is CI-wireable

**webin-cli itself is NOT usable in a test.** Verified with `jars/wcli-8.2.0.jar`: it authenticates
**before** reading any file, even with `-validate`.

```
ERROR: Invalid submission account user name or password.
  at uk.ac.ebi.ena.webin.cli.service.LoginService.login(LoginService.java:74)
  at uk.ac.ebi.ena.webin.cli.WebinCli.getSubmissionAccount(WebinCli.java:754)
  at uk.ac.ebi.ena.webin.cli.WebinCli.<init>(WebinCli.java:148)
```
Login is in the constructor, so no offline path exists. Do not plan around it.

**But the validator underneath it is a separate, credential-free library** —
`uk.ac.ebi.ena.sequence:sequencetools` (`webin-cli/build.gradle:31`, `api 'uk.ac.ebi.ena.sequence:sequencetools:2.+'`),
shipped inside the fat jar at `BOOT-INF/lib/sequencetools-2.24.1.jar`. It has **no `main`** — it is
a library — so wiring it in means a ~40-line driver. I wrote and ran one:
`scripts/EmblValidate.java`.

```sh
unzip -o -q jars/wcli-8.2.0.jar 'BOOT-INF/lib/*' -d fat
CP=$(ls fat/BOOT-INF/lib/*.jar | paste -sd:)
javac -cp "$CP" EmblValidate.java
java -cp "$CP:." EmblValidate my.embl
```

It ran to completion **offline, with no Webin credentials, no DB connection and no network**,
against an EMBL flatfile generated by Biopython from RefSeq GenBank. Core of the driver:

```java
EmblEntryReader r = new EmblEntryReader(br, EmblEntryReader.Format.EMBL_FORMAT, f);
SubmissionOptions opt = new SubmissionOptions();
opt.context = Optional.of(Context.sequence);
EmblEntryValidationPlan plan = new EmblEntryValidationPlan(new EmblEntryValidationPlanProperty(opt));
ValidationResult vr = plan.execute(entry);   // -> ValidationMessage list with check IDs + severity
```

**It really re-translates the CDS.** On a deliberately broken 5'-partial CDS it emitted:

```
PLAN ERROR [CDSTranslator-16] Expected and conceptual translations are different.
PLAN INFO  [CDSTranslator-11] organism classified. Recruiting translation table from taxonomy. Using /transl_table="1".
PLAN ERROR [FeatureKeyCheck-3] Qualifier "codon_start" may occur only once for feature "CDS", not "2".
PLAN ERROR [PeptideFeatureCheck_2] Translation of peptide feature must be a part of the translation of CDS feature unless "exception" or "transl_except" qualifiers are present.
```

So for Loculus preprocessing this is a genuine authoritative check on the `.embl` we emit:
it parses the flatfile, resolves the translation table from taxonomy, translates each CDS and
compares against the declared `/translation=`.

**Caveats, all observed:**
- Some ERRORs are *submission-context*, not file-correctness: `LocusTagPrefixCheck1`
  ("prefix not registered with the project") and `EntryMolTypeCheck` fire on a perfectly valid
  RefSeq-derived file. A CI gate must allowlist by check ID, not just count errors.
- Biopython's EMBL writer is not ENA-clean out of the box: `FF.1 Invalid RL line format` (×4) and
  `FT.7 mol_type has different values within the entry`. Useful in itself — it means round-tripping
  GenBank→EMBL via Biopython does **not** produce a submittable flatfile.
- The plan also emits `FIX` severity messages (it has a fixer mode); treat those as advisory.
- **[NOT VERIFIED]** whether `Context.genome` (assembly submissions) behaves the same offline —
  I only exercised `Context.sequence`.
- **[NOT VERIFIED]** whether sequencetools is on Maven Central under that coordinate for a clean
  Gradle dependency; I used the jar extracted from the bundled fat jar.

**Good news for the circular question:** EMBL flatfile is **not lossy** the way GFF3 is. The
round-trip preserved both topology and the origin-crossing join verbatim:

```
ID   NC_003977; SV 2; circular; DNA; ; VRL; 3182 BP.
FT   CDS             join(2309..3182,1..1625)
```
That is the unambiguous representation GFF3 cannot express — worth remembering when choosing an
interchange format for Loculus.

### 3b. VADR alert codes — the CDS-translation subset

Full list (~90) in `scripts/vadr_alt_list.txt`, produced by `v-annotate.pl --alt_list`.
The ones a translator should be tested against:

`mutstart` MUTATION_AT_START (expected start codon absent) · `mutendcd`/`mutendns`/`mutendex`
MUTATION_AT_END (invalid stop / no in-frame stop at all / first stop is *downstream* = readthrough) ·
**`unexleng` UNEXPECTED_LENGTH — complete CDS not a multiple of 3** · **`cdsstopn` /`cdsstopp`
CDS_HAS_STOP_CODON — premature in-frame stop (nt / protein alignment)** · `fsthicft`/`fsthicfi`/
`fstlocft`/`fstlocfi`/`fstukcft`/`fstukcfi` POSSIBLE_FRAMESHIFT (high/low/unknown confidence ×
frame restored or not) · **`mutspst5`/`mutspst3` MUTATION_AT_SPLICE_SITE — intron not `GT`…`AG`** ·
`peptrans` PEPTIDE_TRANSLATION_PROBLEM · `pepadjcy` PEPTIDE_ADJACENCY_PROBLEM (mat_peptides that
must abut don't) · **`deletinf` DELETION_OF_FEATURE_SECTION — one segment of a multi-segment
feature entirely deleted** · `indf5gap`/`indf3gap`/`indf5plg`/`indf3plg`/`indf5pst`/`indf3pst`
INDEFINITE_ANNOTATION at feature boundaries · `ambgcd5c`/`ambgcd3c` AMBIGUITY_IN_START/STOP_CODON ·
`insertnn`/`deletinn`/`insertnp`/`deletinp` oversized indels · `dupregin` DUPLICATE_REGIONS ·
`discontn` DISCONTINUOUS_SIMILARITY (non-colinear = rearrangement) · `extrant5`/`extrant3`
EXTRA_SEQUENCE beyond expected genome ends.

VADR scope, checked in source rather than assumed:
- **Does not consume or emit GFF3.** `v-build.pl` takes GenBank or a 5-column feature table;
  `v-annotate.pl` emits `.tbl`.
- **No circular support** — `grep -riE 'circular'` over `$VADRSCRIPTSDIR` returns nothing.
  But `v-build.pl` on circular HBV *does* emit correctly ordered segments
  `coords:"2309..3182:+,1..1625:+"`, then tags them `canon_splice_sites:"1"` — so it would raise
  spurious MUTATION_AT_SPLICE_SITE at the origin.

## 4. Corroboration / contradiction of the nextclade findings

I ran nextclade 3.23.0 (`micromamba run -n loculus-nextclade nextclade3`) directly, using the
reference as its own query:
`nextclade3 run -r X.fa -m X.gff3 --output-all out/ X.fa`, scoring
`nextclade.cds_translation.<protein_id>.fasta` against the RefSeq `/translation=`.

### CONFIRMED — circular minus-strand CDS mistranslated (finding #5)

SV40 `NC_001669.1`, `NP_043122.1`, `complement(join(5188..5243,1..16))`, NCBI GFF3 row
`CDS 5188 5259 -` on a 5243 bp genome:

```
truth                          MQRPRPPRPLSYSRSSEEAFLEA   (23 aa)
nextclade                      RLGL*AIPEVVRRLFWRPRCRGRG  (24 aa, 1 internal stop)
= revcomp(A)+revcomp(B)        RLGL*AIPEVVRRLFWRPRCRGRG  ← exact match to the buggy form
correct revcomp(A+B)           MQRPRPPRPLSYSRSSEEAFLEA
```
Nextclade's output is **character-for-character** the predicted `revcomp(A)+revcomp(B)` artefact.

### REFINED — the bug is minus-strand × wrap, *not* circular generally

This narrows the finding considerably and is the most useful thing here:

| genome / case | nextclade |
|---|---|
| SARS-CoV-2 `NC_045512.2` — overlapping ORF1ab ribosomal-slippage join | **12/12 exact** ✅ |
| HBV `NC_003977.2` — circular, **plus-strand** origin-crossing (`CDS 2309 4807`) | **7/7 exact** ✅ |
| SV40 `NC_001669.1` — 6 ordinary CDS + 1 **minus-strand** wrap | **6/7** — only the wrap fails |
| SV40 `NP_043127.1` large T — minus-strand **spliced, non-wrapping**, 708 aa | exact ✅ |
| synthetic HBV wrap as two rows / as out-of-range, plus strand | both **832 aa exact** ✅ |

So nextclade's circular support works on the plus strand, and its minus-strand splicing works.
Only the **intersection** — minus strand *and* origin-crossing — is broken. Note nextclade is
*better* than gffread and AGAT on the SARS-CoV-2 overlapping join, where gffread heap-corrupts
(`malloc(): corrupted top size`, then exits 0) and AGAT emits a 7096 aa protein with 172 internal
stops.

### CONFIRMED — GFF row-order dependence (finding #1)

Same CDS, same FASTA, identical rows, only file order differs:

```
c3_asc  (rows ascending)   GTNTSNQVAVLYQDVNCTEVPVAIHADQLTPTWRVYSTGS   1274 aa  WRONG
c3_desc (rows descending)  MFVFLVLLPLVSSQCVNLTTRTQLPPAYTNSFTRGVYYPD   1274 aa  correct
```
gffread and AGAT both give the correct protein in **both** orders. This also confirms the
"latent" characterisation: NCBI emits minus-strand rows descending, so real RefSeq does not trip
it — but any `sort -k4,4n` or `gffread -o` round-trip activates it, and my ascending file proves it.

### CONFIRMED, and worse than "ignored" — the phase column (finding #4)

A legitimate 5'-partial CDS does not merely translate in the wrong frame — it makes the **entire
annotation unloadable**:

```
Length of a CDS is expected to be divisible by 3, but the length of CDS 'S' is 3820
  (it consists of 1 fragment(s) of length(s) 3820). This is likely a mistake in genome annotation.
Location: packages/nextclade/src/gene/gene_map.rs:177
```
`21565..25384` with `phase=1` is 3820 nt; honouring phase gives 3819, divisible by 3. Nextclade
never subtracts phase, so it rejects the file. (`phase=2`, length 3821 → same error.)
This matters for Loculus/ENA, where 5'-partial CDSes are routine.

### CONFIRMED — panic on out-of-range coordinates (finding #2)

Out-of-range CDS **without** `Is_circular`:
```
The application panicked (crashed).
Message: index out of bounds: the len is 3184 but the index is 3184
```
With `Is_circular=true` the same file translates correctly, so the flag *is* read — the failure is
the missing-flag path. For comparison, `gt gff3validator` produces a clean diagnostic here
(`range (2309,4807) … is not contained in range (1,3182)`), and ENA's `EntryFeatureLocationCheck`
covers the same condition.

### CONFIRMED — `transl_table` ignored

`transl_table=4` on a CDS with an internal TGA: nextclade gives `MYSFVSEET*TLIVNSVLLF` (table 1)
where table 4 requires `MYSFVSEETWTLIVNSVLLF`. **No tool tested honours a per-CDS GFF3
`transl_table`** — gffread has no option at all, AGAT only a global `--table`. Nextclade is in
universal company here; it is still wrong, and ENA's `CDSTranslator-10`…`-15` show the behaviour
NCBI/ENA expect.

### Good behaviour worth noting

Dangling `Parent` produces a clean, actionable error listing the offending features — not a panic.

## Verified recipe (re-checked independently, 2026-09-15)

The jar was not persisted with the scripts, so here is the fetch that works. **The release tag has
no `v` prefix** — `.../download/v8.2.0/...` 404s and curl writes a 9-byte file that unzip then
rejects with a confusing "not a zipfile". Get the URL from the API rather than guessing:

```sh
gh api repos/enasequence/webin-cli/releases --jq '.[0].assets[].browser_download_url'
curl -sL -o wcli.jar https://github.com/enasequence/webin-cli/releases/download/9.0.3/webin-cli-9.0.3.jar
unzip -o -q wcli.jar 'BOOT-INF/lib/*' -d fat        # ships sequencetools-2.33.2.jar
CP=$(ls fat/BOOT-INF/lib/*.jar | paste -sd:)
javac -nowarn -cp "$CP" EmblValidate.java && java -cp "$CP:." EmblValidate my.embl
```

Runs offline, no credentials. JDK 21 (the devcontainer default) is enough.

**It has teeth on translations** — confirmed by mutation rather than assumed. Changing one residue
of a `/translation` in an otherwise valid file raises
`CDSTranslator-2 "Expected and conceptual translations are different"`, which is absent on the
unmodified file. So a clean run means ENA re-translated every CDS and agreed.

### It found two real bugs in Loculus's EMBL output

Run against `preprocessing/nextclade/tests/flatfiles/single_segment.embl`:

| | errors |
|---|---|
| before | 6 |
| after the fix below | 1 |

The one that remains is `SourceFeatureQualifierCheck8: Organism is not Submittable: "Test Ebola
Sudan Virus"` — an artefact of the fixture's invented organism, not a code defect.

1. **`/molecule_type` should be `/mol_type`** in the source feature. The value was already a valid
   INSDC mol_type; only the qualifier name was wrong. Three checks fire on it: `FT.9`,
   `QualifierCheck-1`, `FeatureKeyCheck-7`.
2. **The ID line carried `RNA`**, which `EntryMolTypeCheck` rejects — it must be the full INSDC
   value, `genomic RNA`. Note **Biopython warns `Non-standard molecule type: genomic RNA` for the
   value ENA requires**, so the warning is Biopython being conservative and should not be "fixed".
